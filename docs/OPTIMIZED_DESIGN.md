# Rice SapFlow 优化设计与实物验收

当前版本使用嘉立创 EDA 专业版原生工程和 ESP32-C3 固件。目标是双点温度采集、受控热脉冲、WiFi 数据查看及原始响应导出。软件与 CAD 检查不能替代实物供电、探头热耦合和茎流标定。

## 电路与实际功能

- 主控保留 ESP32-C3 SuperMini 插拔模块；两排 1×8 母座 C27438，现有排距 17.78mm。实际模块型号和孔距尚未确认。
- 5V 由主控模块 USB 供电。模块板载稳压器提供 3.3V，主板没有另加 AMS1117。外部 5V 与 USB 同时接入的供电方式没有设计和验证。
- U4 是 HT7530-7（C259866），VIN 接 5V，OUT 提供标称 3.0V，CE 接 HEATER_GATE。输入、输出分别配置 10µF 与 100nF。
- Q1 是 AO3400A，低侧切换 HEATER_RETURN；栅极经 100Ω 连接 HEATER_EN，100kΩ 下拉。CE 与 MOS 栅极共用控制，复位、未授权或故障时关断。已删除 SJ1，避免误选 5V。
- R5 改用 YAGEO AC0603DR-07470RL（C227500），470Ω、±0.5%、0.1W。替代 PRF18 过温检测 PTC。3.0V 时理想电流为 6.383mA，功率为 19.149mW；200ms/3s 脉冲对应约 3.83mJ/57.45mJ。实际功率取决于负载电压和阻值，应测量，不能用理想值证明温升或量程。
- U2/U3 保留 TMP117MAIDRVR，地址分别为 0x48（ADD0 接地）和 0x49（ADD0 接 3.3V）。ALERT 与 EP 电气不连接。C5/C6 去耦采用 Samsung CL05B104KO5NNNC（C1525），100nF、0402，保持各自电源附近；四个过孔已移到焊盘外，降低焊接吸锡风险。热接触材料、EP 锡膏/钢网处理、覆膜和贴装应单独确认。
- U2、R5、U3 位于同一直线；每颗温度传感器到加热器中心约 3.0mm。尚无实测证明该间距适合目标水稻茎秆。
- J1/J4 均为 Hirose FH12-6S-0.5SH(55)（C202118）底接触插座；探头端采用插座和可拆 FFC，当前版本没有金手指插入端。
- TP1..TP6 改用单孔测试焊盘，借用单针排针封装，均不安装、不进入 BOM。分别为 5V、3.3V、GND、SDA、SCL、HEATER_RETURN。

## 线序与模块核对

| FFC 引脚 | 网络 | 用途 |
|---|---|---|
| 1 | +3V3 | 两颗 TMP117 电源 |
| 2 | GND | 传感器参考地 |
| 3 | SDA | I²C 数据 |
| 4 | SCL | I²C 时钟 |
| 5 | HEATER_VCC | 3.0V 加热电源 |
| 6 | HEATER_RETURN | MOS 切换的加热回流 |

FFC 采用 6Pin、0.5mm 间距，与 FH12 要求的 0.3±0.05mm 插入厚度匹配。排线同面/异面接触取决于两块板的实际摆放和翻折方向：断电时用万用表逐项证明 J1.1 对 J4.1、直到 J1.6 对 J4.6，不能靠外观判断线序。禁止带电插拔。

当前 J2 从 1 到 8 的网络是 5V、GND、3V3、SDA、SCL、NC、HEATER_EN、NC。按常见 SuperMini 排列对应 GPIO4=SDA、GPIO3=SCL、GPIO1=HEATER_EN；原交接所称 GPIO0/1/3 与这组排针连接不一致。固件暂用 4/3/1。实际品牌/板型必须确认，必要时同时改原理图、PCB 和固件，不应只改其中一个。

实际模块的天线位置和推荐覆铜禁布区也需核对。目前母座和底板不能视为已与任意 SuperMini 完成机械及射频兼容验证。

## 固件使用

源文件位于 `firmware/RiceSapFlow/`，目标 FQBN 为 `esp32:esp32:esp32c3:CDCOnBoot=cdc`，已用 Arduino ESP32 core 3.3.12 编译。

```sh
arduino-cli compile --fqbn esp32:esp32:esp32c3:CDCOnBoot=cdc firmware/RiceSapFlow
c++ -std=c++17 -Wall -Wextra -Werror firmware/test_measurement.cpp -o /tmp/rice-measurement-test
/tmp/rice-measurement-test
```

本次没有烧录实物。接入 USB 后，115200 波特率串口显示 `RiceSapFlow-xxxx` 热点及每次启动生成的密码。浏览器访问 `http://192.168.4.1`，用户名 `admin`，密码与热点相同。网页显示两点温度、状态、加热响应曲线和 CSV 下载。

设备每 100ms 同时触发两颗 TMP117 的单次转换，读取 DATA_READY 后再获取温度；校验设备 ID、I²C 返回值、转换超时、样本新鲜度。温度解码为有符号 16bit × 0.0078125°C。传感器断开、超时、温度超过 40°C 或相对加热前基线升温超过 2°C，均锁定故障并关断。

每次脉冲都要重新准备；准备前需要至少 20 个新鲜样本，最近基线波动不超过 0.15°C。准备授权 60s 失效。默认脉冲 200ms，可选 100..3000ms；两次起始至少间隔 120s，观测窗口 90s。独立 `esp_timer` 到时将 GPIO 拉低，网页或主循环阻塞不会延长本次脉冲。

CSV 保存最近 1200 个原始样本，包含温度、脉冲起始时间、基线温升和阶段编号；阶段 0/1/2/3 对应 idle/heating/observing/fault。为避免导出阻塞采样，加热和观测期间拒绝 CSV 下载，可用串口记录。网络温度曲线为每秒显示，完整采样记录约 10Hz。停止按钮立即关断；重新检测不会自动加热。

热比仅在两点升温均达到 0.05°C 且样本有效时输出，其余为 null。没有植入通用茎流公式或伪造标定系数，接口 `sap_flow` 始终为 null，`calibrated=false`。

## 实物验收顺序

1. 确认 SuperMini 的完整型号、两排孔距、针脚方向及 USB/3.3V 稳压能力；核对 FFC 逐针映射。
2. 暂不接植物。上电、复位、启动失败时测量加热回路保持关闭。用 470Ω 假负载，准备并执行一次 200ms 脉冲，用示波器同时看 CE、MOS gate、加热负载电压和关断时刻；再检查 3s 上限和串口/网页阻塞时关断。3V 只在 CE 有效时出现，关断时输入不应持续供能。
3. 实测 5V、3.3V、HT7530 输出、负载电流和电阻功率；每一路应符合元件手册和实物供电能力。验证电容极性与接插件装配方向。
4. 双传感器在同一恒温源中比较，记录零点差、噪声、采样时序和必要的校准参数。拔掉任一传感器，应进入故障并关闭加热；尝试过长脉冲和短冷却间隔，应拒绝。
5. 在替代介质上从 200ms、约 3.83mJ 开始，外部测温确认加热器局部热点和两点温升；传感器的温升阈值不等同于加热器局部温度。没有观察到安全、可重复的信号前，不增加脉冲时长或贴到活体茎秆。
6. 明确上下游方向、传感器和茎秆的接触方式、导热材料、环境温度补偿与热扩散参数。在零流量及独立参考的已知流量条件下获得校准数据，测量重复性和误差，随后才实现体积流量输出。

- [Holtek HT75xx-7 数据手册](https://www.holtek.com.cn/webapi/116706/simHT75xx-7v141.pdf)：引脚表、CE 阈值、应用电容、3.0V 型号及关断行为。

- [Murata PRF PTC 产品规格](https://www.murata.com/-/media/webrenewal/products/thermistor/ptc/prf/bc-e0225x-e.ashx?cvid=20231016060000000000&la=en)：过温检测用途及阻值容差。
- [Hirose FH12-6S-0.5SH(55)](https://www.hirose.com/en/product/p/CL0586-0582-5-55)：连接器型号、底接触与排线配合规格。
